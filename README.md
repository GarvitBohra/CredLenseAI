# CredLensAI

**AI-powered credit risk platform for lenders.** Predict the probability that a borrower will default, see *why* with explainable AI, and monitor risk across a loan portfolio.

**Live demo:** https://frontend-theta-gules-33.vercel.app/
**API docs:** https://credlenseai.onrender.com/docs

> Demo login: `demo@credlens.ai` / `demo123`
> The backend runs on a free tier that sleeps when idle, so the first load can take 30-60 seconds.

> **Disclaimer:** all data is synthetic. This is a learning/demo project, not a validated credit model. Do not use it for real lending decisions.

---

## What it does

| Feature | Description |
|---|---|
| **Risk assessment** | Enter a borrower's details and get a default probability, a risk band (Low / Medium / High) and a suggestion (Approve / Review / Reject). |
| **Explainable AI** | Every score comes with the top 5 factors behind it (SHAP values), shown as bars with plain-English reasons. |
| **Portfolio dashboard** | KPI cards, average risk over time, risk-band distribution, highest-risk loans and alerts for loans above the 35% threshold. |
| **Loans** | Searchable, filterable, sortable list of every loan, with a detail page showing its explanation. |
| **CSV upload** | Score a whole batch of loans at once (up to 5,000 rows). A downloadable template is provided. |
| **Multi-tenant** | Each organization only sees its own loans. Login uses JWT with hashed passwords. |

## How it works

```
 Browser (React on Vercel)
        |  REST + JWT
        v
 FastAPI backend (Render)  --->  PostgreSQL (Neon)
        |
        +-- predictor.py: loads ml/model.joblib
            -> default probability (XGBoost)
            -> top 5 factors (SHAP)
```

The ML model is trained offline and committed as `ml/model.joblib`. The backend loads it once at startup, so there is no separate ML service.

### The model
- **Data:** 8,000 synthetic borrowers generated by `ml/generate_data.py` (about 15% default rate).
- **Features:** age, income, loan amount, interest rate, debt-to-income, credit utilization, past delinquencies, credit history length.
- **Model:** XGBoost classifier (150 trees, depth 3). Test AUC is about **0.76**.
- **Risk bands:** Low < 15%, Medium 15-35%, High >= 35%.
- **Explanations:** SHAP `TreeExplainer`. Positive values push risk up, negative values pull it down.

## API

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/auth/login` | Get a JWT token |
| POST | `/predict?save=true` | Score one borrower (optionally save to portfolio) |
| POST | `/portfolio/upload` | Score and import a CSV |
| GET | `/portfolio/summary` | KPIs, risk bands, trend |
| GET | `/portfolio/loans?risk=High&q=name` | List loans |
| GET | `/portfolio/loans/{id}` | One loan with its explanation |
| GET | `/portfolio/alerts` | Loans above the risk threshold |
| GET | `/health` | Health check |

Interactive docs are available at `/docs` on the backend.

Rows that fail validation (same rules as `/predict`) are skipped and reported back with their row numbers. Optional `created_at` (a date) lets you import historical loans into the right month of the trend chart.

CSV columns: `borrower_name` (optional), `age, income, loan_amount, interest_rate, debt_to_income, credit_utilization, past_delinquencies, credit_history_years`.

## Run it locally

### Option A: Docker (one command)
```bash
docker compose up --build
```
- App: http://localhost:5173
- API docs: http://localhost:8000/docs

Stop with `docker compose down`. Add `-v` to also wipe the database.

### Option B: without Docker
```bash
# Backend (uses SQLite by default)
cd backend
pip install -r requirements.txt
python seed.py
python -m uvicorn main:app --reload      # http://localhost:8000

# Frontend (new terminal)
cd frontend
npm install
npm run dev                               # http://localhost:5173
```

### Retrain the model (optional)
```bash
cd ml
python generate_data.py
python train.py
```

### Run the tests
```bash
cd backend
python -m pytest tests
```
The tests cover login protection, prediction output (probability plus 5 factors), CSV upload counts and organization isolation.

## Deploy for free

1. **Database:** create a free project on [Neon](https://neon.tech) and copy the connection string.
2. **Backend:** create a Render web service from this repo.
   - Runtime: Docker, Dockerfile path `backend/Dockerfile`, build context = repo root.
   - Environment variables:
     - `DATABASE_URL`: your Neon connection string
     - `SECRET_KEY`: a long random string (**required**; the backend refuses to start on Render without it)
     - `CORS_ORIGINS`: your Vercel URL (no trailing slash)
3. **Frontend:** import the repo into [Vercel](https://vercel.com).
   - Root directory: `frontend` (framework preset: Vite).
   - Environment variable `VITE_API_URL`: your Render URL (no trailing slash).
   - `VITE_API_URL` is baked in at build time, so redeploy after changing it.

Pushing to `main` redeploys both services automatically.

## Known limitations
- Synthetic data only; the model is not validated for real credit decisions.
- The free Render instance sleeps when idle and has limited memory.
- The demo login is public. Change `SECRET_KEY` and remove the seeded users before any real use.
